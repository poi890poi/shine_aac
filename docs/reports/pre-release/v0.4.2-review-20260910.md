# v0.4.2 pre-release review and benchmark

Status: **NOT READY for release.** One confirmed accessibility defect and two
unresolved optical verification gates block approval. This is a review, not a
release publication. Application behavior and artwork remain unchanged.
Candidate application source: bd243b1 (version 0.4.2, code 62).
Existing unrelated documentation edits are excluded from candidate commits.

Scope: release review, verification tooling corrections, and benchmarking. Preserve
app behavior, thresholds, artwork, stored data and user settings. Test phone/tablet
only during acknowledged exclusive windows with shared serial mutexes and verified
cleanup. Only manifest-declared public media may drive the optical tests.

Known baseline defect: optical-20260910-223420 labelled five successful camera
activations MISS because older log events were evicted. Each attempted interval
contains one timestamped activation in the raw log. Fix the harness observer to
retain unique epoch/PID/TID/payload event identities across snapshots. Fail on
unidentified activation evidence. Do not weaken duplicate or zero-input checks.
This changes verification only; it does not modify the detector or app timing.
Regression: RotatingActivationLogTest reproduces the old false MISS and exercises
rollover, overlapping reads, empty reads, independent sources, duplicate events,
and invalid identities. All 129 Python harness tests pass after the additional
exact-target navigation regression. Other harness corrections discover web unit
files explicitly on Node 24 and assert the approved two-line scan status.

The installed preview artifact uses the candidate's unchanged application sources
with a separate package ID. Canonical APK assembly and unit tests are also required;
preview physical evidence alone does not verify main-package install/upgrade behavior.

Benchmark criteria: keep functional accuracy separate from timing. Measure core
communication/scanning, renderer draw submission and frame intervals separately,
and native face-analysis timing only where telemetry supports it. Report p95 only
from per-sample data, never infer it from window averages. No optimization or
speedup claim without comparable immutable inputs and repeated runs. GPU parity
and aligned-pixel checks remain independent correctness gates.

Release audit includes non-ancestor branches, full reflogs, stashes, locked worktree
artifacts and the previous recovery matrix. Unresolved P0/P1 findings block release.
No version bump, tag, Play upload, or release publication is part of this review.

## Findings established during this review

1. **P1 accessibility:** source and packaged browser gates both fail the long
   English suggestion scenario at 200% text size. In a 320 x 694 CSS-pixel view,
   ACCESSIBILITY remains two columns and shrinks from the requested 40 px to
   15.7 px. The ordinary 393 x 851 view displays it at 20 px. No clipping occurs,
   but the larger-text setting loses its benefit. Keep the design unchanged
   pending image review; do not relax the existing readability assertion.
2. **P1 full optical verification:** optical-20260910-234700 correctly recorded
   all 15 inputs, but the intended uncomfortable selection produced rest.
   The target cell was active at epoch 1789055792.684; the harness started its
   attempt at 1789055793.187; scanning wrapped at 1789055796.693, Blink appeared
   at 1789055797.034 and activation occurred at 1789055798.422. The app then
   committed rest. This is a demonstrated end-to-end timing mismatch. It does
   not establish a detector miss or justify changing app thresholds. Presenter
   preparation/delivery latency must be separated from app processing before
   rerunning the two full normal-use sessions.
3. **P1 cheek gate coverage:** optical-20260911-000004 stopped before calibration
   because the public cheek face measured 50.1% of preview height, below the
   enforced 55-82% range. Correct the rig stimulus geometry, verify the whole
   face with margin, then rerun calibration and normal-use/stress cases. Do not
   call this a production cheek-detector failure.

## Benchmarks

- Communication: all 103 tasks reachable, all per-task limits and paired gates
  pass; 95 tasks unchanged, 8 improved. Modeled switch total 808 -> 802; modeled
  scan time 4,993,800 -> 4,747,200 ms (4.94% lower). These are modeled task costs,
  not measured user speed. Three measured suite passes after warmup took
  515.4 / 540.7 / 518.5 ms on Node 24.19.0.
- Million-entry adversarial dictionary: cold prefix preparation 468.5 ms;
  10,000 subsequent scan transitions read no dictionary entries. Empty English
  input read 8 entries in 2.16 ms; empty zh-TW read 45 in 1.74 ms.
- Browser scanning: 80 row + 80 cell transitions at 300 ms requested interval.
  Mean intervals 306.1 / 305.6 ms; p95 314.8 / 315.9 ms; maxima 316.4 / 317.0 ms.
  Activation transitions took 2.0 / 4.7 ms. Existing timing gates pass.
- Tablet native face analysis: 1,100 frames across 22 windows; weighted mean
  63.02 ms, maximum observed frame 90.858 ms. Telemetry provides window averages
  and maxima, so per-frame p95 is unavailable. This excludes camera delivery and
  downstream AAC/UI work. Public media comes from one licensed subject; this is
  not evidence of accuracy across users, poses, lighting or disabilities.
- Desktop Canvas/WebGL ABBA comparison: draw submission medians 2.2 / 2.4 / 2.4 /
  2.2 ms; p95 2.8 / 3.6 / 3.2 / 3.1 ms. GPU parity passed, but this desktop
  workload shows no WebGL submission-time speedup. These are headless host
  measurements, not Android compositor latency or proof of overlay assignment.

## Physical renderer benchmark and cleanup

Same seed/state sequence, 30 warmup frames followed by 120 measured frames per
run, in Canvas2D / WebGL / WebGL / Canvas2D order. Timed frames contain no pixel
readback. Measurements are browser draw submission and requestAnimationFrame
intervals, not GPU completion, touch-to-photon latency, or SurfaceFlinger overlay
assignment. These short runs do not establish sustained thermal performance.
