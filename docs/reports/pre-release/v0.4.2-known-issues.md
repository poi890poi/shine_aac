# v0.4.2 deferred issues

## Locked read layout replaces the ordinary board

Status: deferred; do not combine with the scan-highlight styling repair.

Observed on the physical phone after selecting SAY with after-read mode replay
(鎖定版面): the ordinary board and text-history context were replaced by one
full-height row containing only Speak / Clear / Edit.

Expected: 鎖定版面 remains visually unobtrusive and changes scanning behavior
without replacing the ordinary communication layout. 對話顯示 remains the
separate mode allowed to transform the display.

Known cause: boardRows() returns speechLockRows() for every active
speechLockMessage, regardless of after-read mode. Existing unit and browser
tests incorrectly encode the shared three-control replacement board as the
expected behavior. The behavior originated in 43aa414 and was retained by
eb4909e.

Evidence: the 2026-08-27 physical-device log recorded speechLockMode replay,
phase SpeechLock, and a single rendered row [Speak, Clear, Edit]. The runner
restarted before preserving a screenshot.
