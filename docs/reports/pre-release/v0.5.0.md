## Release gate status

### Long-word resize defect — reproduced on shipped boards

The failing `scenarioLongEnglishSuggestionSpans` browser test replaces the
normal English symbols with eight words and three function keys, supplies four
custom ACCESS-prefixed dictionary entries, then reduces the viewport to
320 × 694 CSS pixels and forces a 40 px tile font with CSS. In that fixture,
ACCESSIBILITY retains two columns and fits down to 15.7 px. The content-only span
cache prevents remeasurement for unchanged content. This demonstrates a test
failure; it does not alone establish a user-facing failure in the shipped board.

The short three-row, four-column static board shown in the proposed mockup is
test data, not a shipped preset. The user identified that mismatch. The mockup
and its approval request are withdrawn. A fresh browser baseline using shipped
symbols and dictionaries renders 13 rows for English, including the alphabet,
at both 393 × 851 and 320 × 694. Its initial suggestions render at 20 px and
18 px respectively without clipping. This baseline used no forced font override
and does not prove 200% scaling or long-word behavior. Internal evidence:
`.tmp/release-v050/shipped-board-check.json` and matching screenshots.

The subsequent controlled comparison uses the full shipped symbols and built-in
dictionary, restores `access` or `accessibil` as the normal draft before page
startup, and compares a 393 × 851 → 320 × 694 resize with a fresh page at
320 × 694. It applies no custom dictionary, reduced board or font override.
Both the English profile and Zhuyin's embedded-English category reproduce:

| Built-in completion | After resize | Fresh page at the same width |
| --- | --- | --- |
| ACCESSIBILITY | 2 columns; 15.7 px label against 18 px base | 3 columns; 18 px label |
| ACCESSORIES | 2 columns; 17 px label against 18 px base | Fitting suggestions selected at 18 px |

The `accessibil` comparison reproduces the original readability symptom in the
real 13-row board. Cached geometry is stale after resize; a fresh measurement
already produces a readable one-line layout. Internal evidence:
`.tmp/release-v050/real-longword-matrix.json` and its eight matching screenshots.
The earlier baseline JSON was subsequently rerun with a properly restored draft;
use this named matrix for the controlled long-word comparison.

This is a release-blocking failure of the documented 18 px normal-board floor.
The correction must preserve active scan targets, tile ordering and timing, and
the existing one-line board policy. It does not require the withdrawn two-line
redesign. At the end of the initial investigation, application source and the
browser assertions were unchanged. The subsequently approved corrections and
test changes are recorded below.

### Approved accessibility corrections — September 12

Implementation, policy and regression tests are committed as `a9d3e94`.

The suggestion cache now includes geometry and defers geometry-only regrouping
while scanning. At the existing review pause it recomputes spans. The regression
uses the complete shipped English and embedded-English boards with the built-in
dictionary and restored `accessibil` draft, comparing resize with fresh load.
It separately checks active target, candidates and deadline, and return to review.
The old implementation fails this real-board regression at 15.7 px.

The synthetic custom-dictionary test previously required an unbroken
ACCESSIBILITY label to remain exactly 40 px inside a 320 px viewport. That
requirement conflicts with the existing one-line fitting exception. It now
requires expansion before fitting, one line, no clipping and the unchanged
18 px release floor; fitting below the requested size is permitted only after
using the full row. This is a deliberate correction to the test contract, not
evidence that the synthetic board is a shipped product layout. Its setup now
keeps the initial review pause instead of inadvertently waking the scanner.

The header retains two status lines, keeps words intact and switches to a
named compact Settings gear only when its full label crowds the status.
The gear retains a minimum 48 CSS-pixel target. A real Android 200% preview
was inspected before implementation. No Android text-scale override was added.

The corrected canonical arm64 APK has SHA-256
`d0eeb65c809fcdbba615556f838c2dfb41aeda4dac7ea131f2bbba2afd5cc342`.
`device-test.bat --header-layout` installed it over the phone's main package,
pulled it back and confirmed the same hash. At actual Android 100% and 200%,
status words remain intact, voice and board fit, and scan-highlight edge deltas
are zero. Android exposes the gear with its Settings name; tapping its native
accessibility bounds opens the native Settings activity. The 200% target is
approximately 52 by 54 CSS pixels. Final evidence is in
`.tmp/header-layout/RFCR91GWXLX-1789185908380/`.

Two preliminary harness failures are retained: an early measurement sampled
before WebView text zoom settled, and the first UIAutomator request returned an
unexpanded WebView. The final harness requires 1.2 seconds of stable geometry,
checks that the screenshot agrees with those measurements, and retries named
Android accessibility discovery within a fixed limit. It never substitutes a
guessed tap coordinate. This closes the earlier header-specific automation gap.
All original display settings were restored and verified, the display was
verified OFF under the shared mutex, and the phone window was explicitly released.

Architecture/docs checks, 205 quick core tests and 53 web unit tests pass on the
corrected source. The four-ABI APK package and signed AAB rebuilds pass. The AAB
SHA-256 is `1276e123463722786cce279dd6e6682c84f1e3009db717f3a1cec406d60f1e2f`.
The earlier complete optical gates cover unchanged detector/activation code;
they were not repeated or presented as a new sustained-load benchmark.
Full browser evidence: `.tmp/release-v050/full-web-after-accessibility.log` and
`.tmp/release-v050/packaged-web-after-accessibility.log`. The additional return
to review assertion passes in both focused source and packaged runs, recorded
