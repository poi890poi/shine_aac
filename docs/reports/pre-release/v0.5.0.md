## Release gate status

### Long-word resize defect — reproduced on shipped boards

The failing `scenarioLongEnglishSuggestionSpans` browser test replaces the
normal English symbols with eight words and three function keys, supplies four
custom ACCESS-prefixed dictionary entries, then reduces the viewport to
320 × 694 CSS pixels and forces a 40 px tile font with CSS. In that fixture,
ACCESSIBILITY retains two columns and fits down to 15.7 px. The content-only span
cache prevents remeasurement for unchanged content. This demonstrates a test
failure; it does not alone establish a user-facing failure in the shipped board.

The short three-row, four-column static board shown in the proposed mockup is
test data, not a shipped preset. The user identified that mismatch. The mockup
and its approval request are withdrawn. A fresh browser baseline using shipped
symbols and dictionaries renders 13 rows for English, including the alphabet,
at both 393 × 851 and 320 × 694. Its initial suggestions render at 20 px and
18 px respectively without clipping. This baseline used no forced font override
and does not prove 200% scaling or long-word behavior. Internal evidence:
`.tmp/release-v050/shipped-board-check.json` and matching screenshots.

The subsequent controlled comparison uses the full shipped symbols and built-in
dictionary, restores `access` or `accessibil` as the normal draft before page
startup, and compares a 393 × 851 → 320 × 694 resize with a fresh page at
320 × 694. It applies no custom dictionary, reduced board or font override.
Both the English profile and Zhuyin's embedded-English category reproduce:

| Built-in completion | After resize | Fresh page at the same width |
| --- | --- | --- |
| ACCESSIBILITY | 2 columns; 15.7 px label against 18 px base | 3 columns; 18 px label |
| ACCESSORIES | 2 columns; 17 px label against 18 px base | Fitting suggestions selected at 18 px |

The `accessibil` comparison reproduces the original readability symptom in the
real 13-row board. Cached geometry is stale after resize; a fresh measurement
already produces a readable one-line layout. Internal evidence:
`.tmp/release-v050/real-longword-matrix.json` and its eight matching screenshots.
The earlier baseline JSON was subsequently rerun with a properly restored draft;
use this named matrix for the controlled long-word comparison.

This is a release-blocking failure of the documented 18 px normal-board floor.
The correction must preserve active scan targets, tile ordering and timing, and
the existing one-line board policy. It does not require the withdrawn two-line
redesign. The browser gate remains open and its assertion is unchanged. No
application source was changed during this investigation.

### Optical end-to-end coverage — complete on Preview

An attempt to update the tablet's main package stopped at signature mismatch.
Inspection established that its installed 0.4.1 is Play-signed, whereas the phone's
installed 0.4.2 has the pinned direct-install certificate. No app was uninstalled.
The tablet Preview package provides a separate upgrade-compatible test surface;
canonical direct-install upgrade verification belongs on the phone.

The first complete blink-use attempt using an older fixture failed at its initial
activation. Camera analysis was running without face scores. This is not proof
of a detector regression: fresh atlas discovery found a different framing, and
fresh native long-blink calibration subsequently passed with good saved quality.
The corrected-fixture blink communication scenario passed: 20 selections and
four speech turns (`幫忙喝水`, `不舒服休息`, `痛幫忙`, `hi`), including a deliberate
wrong choice, Undo, clear and an English/Zhuyin round trip. It used 49 observed
camera activations over 1,315.944 seconds. No repeated detector/stress sequences
were run. Both displays were verified OFF after restoration. Evidence is in
`test-results/optical-20260912-093806/`.

Fresh native cheek calibration passed using the manifest's public smiling
source. Measured face height was 65.6% of the preview, near the approximately
70% target; the model was accepted after one unlabeled twitch sequence in
8.7 seconds. Evidence is in `test-results/optical-20260912-100120/`. Restoration
and both display-OFF checks passed.

The separate cheek communication scenario also passed: 17 selections and four
speech turns (`廁所`, `累`, `家人`, `ok`), including correction, clear and the
English/Zhuyin round trip. It used 40 observed camera activations over 987.821
seconds. Evidence is in `test-results/optical-20260912-100310/`. No repeated
detector/stress sequences ran. Settings restoration and both display-OFF checks
passed; both device mutexes and the acknowledged window were explicitly released.

Both complete normal-use optical gates are closed for this Preview candidate.
These public-media rig results do not establish cross-user accuracy or sustained
thermal performance. The separate main-package acceptance result is recorded
above; it does not replace optical evidence.

The report previously labelled reused geometry as an atlas PASS. A new real-report
test reproduced that error before the fix. The report now says
`REUSED (not verified this run)`; all 107 optical harness tests pass. Only a fresh
successful atlas is reported as a current geometry PASS.
