# v0.4.1 hotfix issue disposition

## Locked read layout replaces the ordinary board

Status: resolved in the isolated after-read layout fix.

Observed on the physical phone after selecting SAY with after-read mode replay
(鎖定版面): the ordinary board and text-history context were replaced by one
full-height row containing only Speak / Clear / Edit.

Resolution: 鎖定版面 now preserves ordinary board geometry and changes only the
final three cells to 修改 / 朗讀 / 清除 (English: EDIT / SAY / CLR). 對話顯示
shares that generated bottom row as its only board row. Preserved cells remain
visible but reuse the skipped-Zhuyin dim/dashed style and cannot be scanned.

Cause: boardRows() returned speechLockRows() for every active speechLockMessage,
regardless of after-read mode. Existing tests incorrectly encoded the shared
three-control replacement board as expected behavior. The behavior originated
in 43aa414 and was retained by eb4909e.

Evidence: the 2026-08-27 physical-device log recorded speechLockMode replay,
phase SpeechLock, and a single rendered row [Speak, Clear, Edit]. The runner
restarted before preserving a screenshot.

Regression evidence: core tests require flat control-only scanning and
wake-only resume; browser and packaged E2E require the shared bottom row and no
group phases; the standard phone `-SpeechLockUiOnly` path checks replay and
conversation layouts, actual deferred/disabled rendering, all three controls,
and an Android lifecycle pause/resume. Phone screenshots are stored with the
test artifacts for visual review when the physical gate is run.
