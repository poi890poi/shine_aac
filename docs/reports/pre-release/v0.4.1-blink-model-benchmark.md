# 0.4.1 MediaPipe eye-state model benchmark

Status: **Corrected independent-image benchmark; no temporal inputs**

Date: 2026-08-27

Production code changed: **No**

## Scope

This report measures the bundled MediaPipe task as a static eye-state model.
Every frame is evaluated independently in MediaPipe `IMAGE` mode. Dataset videos
are only containers from which images are decoded.

The benchmark does not use timestamps, tracking history, frame order, frame
rate, blink intervals, closure duration, user agility, AAC policy, CameraX, or
Android application behavior. Android evidence is kept separately in
`v0.4.1-blink-app-benchmark.md`.

- Model: `android-inputs/src/main/assets/face_landmarker.task`
- Model bytes: `3,758,596`
- Model SHA-256: `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff`
- Runtime: MediaPipe Python `1.0.0`, CPU/XNNPACK, `IMAGE` mode
- Dataset: EyeBlink8, GPL-3.0
- Dataset archive SHA-256: `856cb82f3437f3c0d94633027cb74cf74186920ca5926aeebb630d715eba9295`
- Data: 8 videos, 4 people, 1 wearing glasses, 70,992 annotated frames

No private/uploaded face media or talking-face dataset was used.

## Labels

For each eye:

- positive: the dataset annotates the eye as 90–100% closed (`FC=C`);
- negative: the eye is visible and the frame is outside an annotated blink;
- excluded: partially closed transition, invisible eye, or non-frontal face.

The bilateral score is the mean of `eyeBlinkLeft` and `eyeBlinkRight`. A
bilateral positive requires both eyes to be annotated fully closed. EyeBlink8
labels image position, while MediaPipe labels anatomical side, so image-left is
compared with `eyeBlinkRight` and image-right with `eyeBlinkLeft`.

## Coverage

The run decoded 71,356 frames. The model returned both blink scores on 70,991 of
70,992 annotated frames: **99.9986% coverage**. The single missing annotated
frame is counted as not closed in the operating-point result.

## Threshold-independent ranking

| Target | ROC AUC | Average precision |
| --- | ---: | ---: |
| Image-left eye | 0.9980 | 0.9339 |
| Image-right eye | 0.9992 | 0.9799 |
| Bilateral | **0.9993** | **0.9791** |

ROC AUC is high because open and closed scores are usually well ordered.
Average precision exposes the remaining overlap, particularly for the
image-left eye. Neither metric selects a usable decision threshold by itself.

`0.55` is shown only because it was used in the earlier exploratory report. It
is not supplied by MediaPipe and is not Android's personalized normalized
threshold.

## Threshold trade-off

The threshold that maximizes F1 on this same dataset is diagnostic and optimistic:

| Target | Threshold | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: |
| Image-left eye | 0.39 | 84.15% | 89.63% | 86.80% |
| Image-right eye | 0.43 | 97.16% | 90.55% | 93.74% |
| Bilateral | **0.41** | **94.37%** | **91.69%** | **93.01%** |

No tested bilateral threshold satisfies both precision and recall ≥97%:

- with precision ≥97%, the best recall is 87.73% at threshold 0.44;
- with recall ≥97%, the best precision is 76.69% at threshold 0.33.

These results are fitted and evaluated on the same four people, so they must not
be used as production thresholds.

## Why closed frames receive low scores

The bilateral fully-closed score distribution overlaps the open distribution:

| Label | p05 | Median | p95 | Minimum | Maximum |
| --- | ---: | ---: | ---: | ---: | ---: |
| Fully closed | 0.3658 | 0.5721 | 0.6909 | 0.2219 | 0.7833 |
| Open/outside blink | 0.0240 | 0.1049 | 0.2148 | 0.0047 | 0.5371 |

MediaPipe's values are blendshape coefficients, not calibrated probabilities of
an anatomically closed eye. Manual review of extreme frames found legitimate
closed annotations with head tilt or a hand near the face, while high-scoring
negative frames included eye touching/occlusion and downward gaze. Those are
static appearance ambiguities, not timing failures.

## Verdict

By a gate requiring precision and recall above 97%, this model/configuration does
**not pass** EyeBlink8. The result does not show that Android long-blink input
fails, because Android personal calibration transforms the raw scores and the
application adds separate temporal logic. It does show that the uncalibrated raw
blendshape coefficient is not accurate enough to be treated as a near-perfect
closed-eye classifier.

The dataset is small and lacks demographic metadata, so the next model decision
requires a broader static, subject-held-out dataset. Do not change the Android
threshold from this same-dataset sweep.

Raw predictions and machine-readable results are generated under the ignored
`test-results/blink-model-eyeblink8-static-20260827/` directory. The reproducible
evaluator is in `scripts/benchmarks/blink_model/`.
