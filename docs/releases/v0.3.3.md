# SHINE AAC v0.3.3

Android version code: 57

Android version code: 56

## Hardware switch input

- The existing switch-input selector adds `Buttons — volume activates`. This
  mode accepts volume-up and volume-down as activation events for devices such
  as Bluetooth shutter remotes that present themselves as volume controls.
- `Buttons — keep volume control` remains the default and preserves normal
  Android volume adjustment while supporting non-volume hardware keys.
- Camera-focus keys join the already supported camera, media, and external
  controller keys.
- Switching between the two modes takes effect immediately through the existing
  selector; no extra checkbox is added.

## Camera setup fixes (code 57)

- Fixed a critical bug where finishing camera setup (`完成`) could land on the
  main scanning board instead of returning to Settings, discarding any unsaved
  settings edits, and could leave blink activation unresponsive (a long blink
  registered its confirmation tone but did not switch) until the app was
  force-restarted. Settings now persist a recovery draft before opening camera
  setup and restore Settings, with the in-progress field values, on the next
  app start if the round trip through camera setup caused the app process to
  be recreated. Native input events are now queued and delivered once the
  WebView has finished loading instead of being silently dropped if a switch
  activation arrives before the page is ready.
- Removed the separate "測試" (Test) button in camera setup. It duplicated the
  screen's existing always-on live blink preview and feedback; the preview
  alone now covers verifying setup.
- Scan timing no longer changes automatically based on the selected switch
  input. Previously, enabling a camera switch profile silently forced the
  camera long-blink timing preset at runtime regardless of what the "Scan
  preset" setting displayed. The "Scan preset" selection is now the single,
  honest source of truth for scan timing in all switch-input modes; pick the
  "Camera long blink" preset explicitly if desired.

## Display

- Added optional higher-contrast display presets ("High contrast (light)" and
  "High contrast (dark)") alongside the default theme, for displays with low
  or biased contrast/saturation. Selectable from Settings and previewed live
  before saving.
- The camera status indicator no longer adds its own layout row/line on
  narrow phones or in the wide landscape layout. It now sits inline next to
  the voice status label, so enabling or disabling it does not shift the rest
  of the top panel.

## Camera switch input

- Auto-calibrated blink-detection parameters are now shared between live
  detection and the recalibration screen, so a recalibration run and normal
  use agree on the same thresholds.
- Fixed camera blink detection not correctly re-arming after an activation,
  which could leave the switch unresponsive until the app was restarted.
- Hardened camera setup and raised the default long-blink threshold.
- Reduced latency in live blink detection.
- Camera switch input can now use either the built-in or an external camera.
- Scanning now pauses automatically when the app leaves the foreground and
  resumes when it returns.

## Revision r2 (version code 57)

## Optical switch setup screen

This release is a usability repair of the camera setup screen, driven by physical-device testing of
v0.3.3.

- The gesture choice is now a two-button segmented control. The previous control was a spinner drawn
  as plain text, which gave no sign that it could be changed. The active gesture is filled and
  outlined; the inactive one is a plain button.
- The screen fits on one page again. The controls no longer scroll: gesture, camera, activation hold
  and zoom are each a single "label plus buttons" row, and the preview takes whatever height is
  left. The static colour legend was removed because the preview now reports tracking state directly.
- The tracking marks follow the face. The preview surface is written by the camera in sensor
  orientation, but only the detector was compensating for it, so the overlay worked in an upright
  frame while the preview stayed sideways. On an upright phone that made pitching the head move the
  box sideways and yawing the head move the box vertically. The preview transform and the overlay are
  now both derived from one geometry function and share the same rotation and mirroring.
- In cheek twitch mode the overlay also draws the face landmarks, not just a box, so a helper can see
  at a glance whether tracking is locked on.
- The preview no longer changes size during setup. The status and metric lines above it now have a
  fixed height, so wording changes cannot resize the preview pane, and the transform is no longer
  applied with placeholder values before the camera reports its real buffer size and rotation.
- Every calibration cue is now both heard and seen. Tones and the on-screen signal are emitted from
  one place, so each step shows a coloured border, a headline naming the step, and the seconds left.
  A tone alone was easy to miss in a noisy room or by a user who cannot hear it.

## Verification
