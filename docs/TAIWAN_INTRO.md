# SHINE AAC 台灣繁體中文介紹

SHINE AAC 是一個面向台灣使用者的輔助溝通專案。它的目標不是取代語言治療、醫療照護或既有 AAC 系統，而是提供一個低成本、可測試、可客製的溝通工具原型，特別關注只能穩定做出一個簡單信號的使用者，例如按一下開關、觸碰螢幕、眨眼、頭部動作或其他二元輸入。

本頁提供三種讀者的入口：

- 想理解核心想法的人
- 協助使用者試用 app 的家人、照顧者、老師或治療師
- 可能參與專案的軟體開發者、照顧者、醫療專家、語言治療師、UX 研究者與測試者

## 核心想法

許多人並不是沒有想法，而是無法用一般方式把想法說出來或打出來。語音障礙、動作控制困難、疲勞、吞嚥或呼吸問題、認知負荷、視覺限制、環境噪音，都可能讓口語或手寫輸入變得不可靠。

AAC 是「輔助與替代溝通」的概念，英文是 Augmentative and Alternative Communication。它包含所有補充或替代口語、書寫的方法，例如手勢、圖卡、溝通板、眼控、開關掃描、文字轉語音裝置，以及平板或手機上的溝通 app。

SHINE AAC 目前專注在一個特定問題：當使用者只能做出很少種類、很低頻率、甚至只有一種可靠動作時，如何仍然讓他能夠選字、組句、發聲，並且修正錯誤。

這也是為什麼 app 使用「掃描」而不是要求使用者直接點選每一格：

1. 畫面會依序亮起一列。
2. 使用者在想要的列亮起時啟動一次開關。
3. app 再依序亮起該列的格子。
4. 使用者在想要的格子亮起時再啟動一次。

這種方法速度不會比直接觸控快，但它把操作需求降到最低。對一些使用者而言，能否穩定完成溝通，比速度更重要。

## 台灣中文方向

台灣使用者需要的不是把英文按鈕翻成中文而已。繁體中文、注音符號、台灣常用詞、照護場景、家庭稱謂、語音輸出、教育與醫療環境，都會影響一套 AAC 系統是否真的能被使用。

SHINE AAC 的台灣中文方向包含：

- 繁體中文介面與說明文件
- `zh-TW` 語言設定
- 注音符號輸入與候選詞
- 短而高價值的溝通詞，例如「要」、「不要」、「幫忙」、「痛」、「喝水」、「廁所」
- 可由協助者調整的掃描速度、停留時間、語音提示與版面
- 離線優先，降低網路、帳號與隱私風險

目前仍是早期原型。它適合小規模試用與回饋，不應被視為正式醫療器材、緊急求救系統或唯一溝通方式。

## 協助者快速開始

協助者可能是家人、照顧者、老師、語言治療師、職能治療師、護理師或志工。第一次試用時，請先把目標放在「看懂操作流程」與「找到合適速度」，不要一開始就要求使用者完成長句。

### 1. 準備設備

- 使用 Android 手機、平板，或電腦瀏覽器版本進行測試。
- 確認音量足夠，並安裝或啟用中文語音輸出。
- 若使用外接開關，先確認它會送出可被 Android 接收的按鍵事件，例如音量鍵、耳機按鍵或藍牙開關。
- 旁邊保留一個低科技備援方式，例如紙本溝通板、眼神 yes/no、照顧者熟悉的手勢。

### 2. 先由協助者試操作

請協助者自己先完成以下動作：

1. 等待列掃描到想要的列。
2. 啟動一次，進入格子掃描。
3. 等待格子掃描到想要的按鈕。
4. 再啟動一次，選取按鈕。
5. 嘗試 `SAY` 發聲、`DEL` 刪除、`UNDO` 復原、`CLR` 清除。

協助者如果自己還不熟，使用者通常會更焦慮。

### 3. 先測試最重要的訊息

早期試用不要追求完整字彙。先確認使用者能否表達高價值需求：

- 是 / 不是
- 要 / 不要
- 幫忙
- 痛
- 喝水
- 廁所
- 停
- 再一次
- 太快 / 太慢
- 我累了

如果使用者可以穩定表達這些訊息，再逐步加入名字、地點、照護流程、娛樂、學校或工作相關詞。

### 4. 調整掃描速度

掃描太快會造成錯過目標，掃描太慢會造成疲勞與挫折。協助者應觀察：

- 使用者是否常常晚一點才按到
- 是否會連按兩次或誤觸
- 是否看得出目前亮到哪一列、哪一格
- 是否在幾分鐘後明顯疲勞
- 是否需要語音提示幫助追蹤掃描位置

一次只調整一個設定。每次調整後，用同一組簡單訊息再測試。

### 5. 記錄試用結果

請記錄實際觀察，而不是只記錄「好用」或「不好用」：

- 使用的設備與輸入方式
- 掃描速度與停留時間
- 成功完成哪些訊息
- 哪些按鈕最常誤選
- 哪些詞不符合台灣日常用法
- 使用者何時疲勞
- 協助者需要哪些設定或說明

這些資料比主觀評分更能幫助改進 app。

## 給潛在貢獻者

SHINE AAC 需要的不只是寫程式。AAC 是語言、動作控制、照護流程、使用者經驗、家庭情境與工程可靠性的交會點。

### 軟體開發者

你可以協助：

- 改善 Android 打包、測試與發佈流程
- 強化離線資料儲存與隱私設計
- 建立更可靠的輸入介面，例如藍牙開關、鍵盤、相機或無障礙服務
- 改善掃描狀態機、錯誤修正、延遲補償與測試覆蓋
- 建立更好的繁體中文詞庫與注音候選排序
- 改善 WebView、瀏覽器與 Android 版本的一致性

請優先保護核心邏輯的可測試性。能在沒有手機、沒有螢幕的情況下測試的規則，應該放在共享核心。

### 照顧者與家人

你最了解使用者的日常。你可以協助：

- 找出真正高頻、高價值的詞
- 說明哪些詞太正式、太長或不自然
- 回報照護流程中的緊急溝通需求
- 測試協助者設定流程是否看得懂
- 協助建立初始個人化版面

請特別回報「使用者想講但找不到」的內容。這通常比新增更多通用詞更重要。

### 醫療與復健專家

醫師、護理師、職能治療師、物理治療師與其他醫療照護者可以協助判斷：

- 使用者適合哪一種輸入方式
- 疲勞、姿勢、視覺、聽覺、注意力與呼吸狀態如何影響操作
- 哪些情境需要備援溝通方式
- 哪些描述可能造成不當醫療宣稱
- 試用過程需要哪些安全界線

本專案需要明確知道自己能做什麼，也需要知道不能承諾什麼。

### 語言治療師與 AAC 專家

你可以協助：

- 檢查台灣中文詞彙是否符合 AAC 使用需求
- 設計核心詞與情境詞的平衡
- 建議不同能力階段的版面
- 評估注音輸入、候選詞與語音輸出的可理解性
- 設計訓練方式，讓使用者與溝通夥伴一起學會使用

請特別指出哪些設計看似方便協助者，實際上會限制使用者表達。

### UX 研究者與設計師

你可以協助：

- 設計小規模試用流程
- 建立觀察紀錄表與訪談問題
- 評估掃描節奏、視覺焦點、按鈕大小、對比與疲勞
- 改善設定介面，讓協助者能調整但不誤改
- 找出使用者、協助者與開發者看到的問題是否一致

SHINE AAC 的使用者不一定能用一般方式填問卷或描述問題。研究設計需要尊重這個限制。

### 測試者

測試者可以協助驗證：

- 不同 Android 手機與平板尺寸
- 繁體中文系統語言
- 中文 TTS 語音
- 音量鍵、耳機鍵、藍牙開關與鍵盤輸入
- 離線啟動
- 螢幕旋轉、休眠、回到前景後的狀態
- 長時間使用後是否仍然穩定

請回報設備型號、Android 版本、輸入方式、重現步驟與截圖或錄影。

## 試用原則

小規模試用時，建議遵守以下原則：

- 不把 app 當作唯一溝通方式。
- 不用它取代醫療判斷、照護判斷或緊急求救設備。
- 先從短訊息與高價值需求開始。
- 每次試用時間要短，避免疲勞。
- 尊重使用者拒絕、暫停或停止的訊號。
- 所有個人化詞彙都應由使用者、家人或主要照顧者確認。
- 回饋時避免公開可識別的個人健康資訊。

## 目前最需要的回饋

- 台灣日常照護情境中，第一層應該放哪些詞？
- 注音輸入與候選詞是否符合台灣使用習慣？
- 掃描速度、第一格停留、錯誤修正是否容易理解？
- 協助者是否能在沒有工程師陪同下完成設定？
- 哪些功能對一到兩位真實使用者最重要？
- 哪些說法可能讓人誤解為醫療承諾？

如果你想參與，請先從具體觀察或小型改進開始。對 AAC 來說，真實使用情境中的小問題，往往比大型功能更重要。
