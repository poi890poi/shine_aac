# zh-TW Phonetic Access Design

Generated: 2026-07-05

## Goal

The `zh-TW` profile should be the primary user-facing profile for Taiwan users. It must be judged as an AAC access system, not as a normal full-keyboard Zhuyin IME.

The constraint is different from normal text entry:

```text
Normal Zhuyin IME: every phonetic symbol is always available.
SHINE AAC scanning: only a small first-level board can stay visible without increasing fatigue and timing errors.
```

Therefore `zh-TW` needs a phonetic access graph:

```text
static first-level Zhuyin symbols
  -> dynamic valid continuation symbols
  -> ranked glyph/phrase candidates
```

## Evidence Policy

Use the best available evidence without pretending it is stronger than it is.

- Taiwan AAC, special education, or clinical materials are preferred when available.
- Traditional Chinese/Zhuyin language data is used for language-specific reachability and candidate ranking.
- English AAC materials may justify general communication functions such as refusal, help request, preference, discomfort, repair, and partner interaction.
- English AAC materials must not directly justify exact Mandarin wording or phrase ranking.
- Japanese kana input may be used only as a structural analogy for progressive phonetic disclosure and candidate conversion; it must not determine the Taiwan Mandarin layout.

## No-Overfit Rule

Benchmark failures may change:

- source-backed ranking weights
- broad AAC communication-function weights
- static-symbol coverage rules
- continuation-symbol ordering
- page and scan-cost penalties

Benchmark failures must not create:

- benchmark-id checks in production code
- phrase-specific shortcuts
- one-off exceptions for individual examples
- translated English sentence targets treated as Taiwan clinical evidence

Bad:

```text
If target is "refuse drink", force 不要喝.
```

Good:

```text
After refusal-class outputs, rank drink, food, medicine, care, and movement actions higher by tagged class.
```

## Phonetic Graph Model

Every dictionary key is treated as a path:

```text
不要 -> ㄅ ㄧ
幫忙 -> ㄅ ㄤ ㄇ ㄤ
喝水 -> ㄏ ㄜ ㄕ ㄨ ㄟ
```

The generated graph answers:

- Which first symbols have the most weighted dictionary coverage?
- Which first symbols are worth static first-level space?
- Which hidden symbols are reachable as valid dynamic continuations?
- Which high-ranked entries have blocked phonetic paths?

The current analysis is generated by:

```text
node scripts/report-zhtw-phonetic-access.mjs
```

The output is:

```text
docs/ZHTW_PHONETIC_ACCESS_REPORT.md
```

## Current Baseline

The current profile exposes 24 static Zhuyin symbols out of 37 total input symbols. Hidden symbols are expected to appear as suggestions only when they are valid continuations from the current prefix.

Current report highlights:

- static first-symbol coverage is above 98% by dictionary weight
- all hidden continuation symbols with dictionary prefixes have at least one visible continuation path
- only a small number of top source-ranked entries are blocked by missing first-level symbols

This does not mean the layout is final. It means the current static/hidden split is measurable and good enough to improve with data instead of hand tuning.

## Optimization Objective

Optimize general access cost:

```text
expected cost =
  static symbol selections
+ dynamic continuation selections
+ candidate selections
+ page cost
+ correction risk
```

Subject to:

- bounded rows and pages
- stable motor layout
- no dead-end static symbols
- no unrelated backfill in typed-buffer suggestions
- no visible continuation symbol unless the resulting prefix has a source-backed candidate or continuation path
- profile-specific logic stays isolated from English

## Sparse Page Policy

Suggestion pages should be as dense as the source data allows, but density must not override relevance.

Allowed fillers:

- exact candidates for the current buffer
- valid next Zhuyin symbols whose resulting prefix exists in source data
- bounded `更多` paging when more useful candidates exist
- repair actions such as `UNDO` when the user has history

Not allowed:

- dead-end continuations such as a symbol that creates a source-empty prefix
- unrelated global defaults after a typed Zhuyin buffer
- broad parent-prefix candidates that replace a more specific buffer unless a separate general ranking rule justifies them

If a very specific prefix has only one or two source-backed candidates, blank cells are better than misleading cells. The report still tracks these sparse pages so future ranking/data changes can improve them without adding special cases.

## Reports And Tests

`docs/COMMUNICATION_BENCHMARK_REPORT.md` measures source-backed communication functions.

`docs/ZHTW_PHONETIC_ACCESS_REPORT.md` measures Zhuyin graph coverage.

Tests protect:

- broad static first-symbol coverage
- hidden continuation reachability
- bounded top-entry blocked paths
- progressive navigation through visible symbols or suggestions
- no unrelated replacement backfill for source-empty finals

These reports are intended to guide future ranking and layout changes. They are not product copy and should not be shown to AAC users.
